## Terms

<!-- Alphabetical by canonical name. One line per term. -->

- **actuate** — Fire the intended fan state at the NodeMCU endpoint (`awair.fans.actuate`). Distinct from **decide**: `decide` produces the intent, `actuate` sends it.
- **aq_ts** — The air-quality block's *own* `current.time`, stored on the **outdoor reading** row alongside `ts` (#71). Air quality is CAMS-backed and hourly while weather is quarter-hourly, so on a perfectly healthy row `aq_ts` lags `ts` by up to an hour — a row stamped 14:15 routinely carries a `us_aqi` measured at 13:00. Before #71 it was parsed and discarded, so nothing downstream could tell. **Not a substitute for `received_at`** (our poll wall-clock) and not the primary key (`ts` is). NULL means the AQI has no known observation time — the air-quality fetch failed for that poll (see **outdoor poll**'s `"partial"`), the row predates #71, or the source published a `current.time` this app refused to date: malformed, or **date-only** (#77 — `datetime.fromisoformat` would read `"2026-07-12"` as midnight and `"2026-07-12+05:00"` as 05:00, both times the source never published) — and the hub renders that as *"no current AQI"*, yellow, rather than folding an undateable number into a green. Deliberately not backfilled by the migration: inventing an observation time is exactly what this column exists to prevent.
- **ceiling** — Per-metric absolute alert threshold on `MetricConfig` (`spikes.MetricConfig.ceiling`). A `ceiling`-tier event opens when the last 2 samples exceed it (bypasses the relative-baseline path). Dashboard renders it as a dashed reference line so autoscaled Y-axes don't visually collapse "still elevated" into "cleared" (#25). Values: co2=1200, voc=2200, pm25=35. Unrelated to the ceiling **fan** hardware; naming collision is intentional-and-fine.
- **connect_readonly** — The query-only SQLite connection (`awair.db.connect_readonly`) the web app opens per request, as against **connect**, which bootstraps the schema and belongs to a process that owns the database. Opened `mode=ro`, so SQLite refuses the write rather than the code merely declining to make it (#73) — every `db` function `web.py` reaches is already query-only, and this keeps it that way. Before #73 each request replayed the whole DDL path: 5 SCHEMA statements plus 6 `ALTER TABLE`s whose duplicate-column errors `_add_column` swallows, at a median ~4× the cost of opening read-only (0.13 ms vs 0.03 ms, measured over 400 opens against an 80k-row database with a live writer) — harmless while a human clicking a dashboard was the only caller, and a schedule once **latest** gave a machine a reason to poll. The trade is that it **cannot create the file**: `create_app` bootstraps once at startup (twice in practice, since gunicorn runs two workers — the same race `_add_column` already tolerates against the pollers) so a fresh install still serves, and a database deleted under a running process now fails the request loudly instead of resurrecting empty. A bootstrap that *cannot* open the path is logged and swallowed rather than raised: `awairelement-web.service` is `Restart=always`, so raising would crash-loop the worker where the pre-#73 code merely 500ed `/api/*` and kept serving `/`. `journal_mode` is deliberately not set from here: it is a write, and the pragma already persists in the file header.
- **decide** — In `awair.fans`, the rate-limit + no-op filter around a **desired action**. Returns a `MitigationDecision` or `None`.
- **desired action** — The verdict `awair.fans.desired_action` derives from the latest co2, the latest pm25 and the fan's **run**: a `Verdict` carrying `"off"` or `"speed1"`, a reason, and the **capped** flag to persist. Since ADR-002 it never consults **event**s.
- **DeviceHealth** — The **indoor** poller's consecutive-status tracker, used to detect the transition between healthy and stale/unreachable readings. Counts runs of `"error"` and `"duplicate"` against a `threshold` (default 10, ~5 min at the 30 s indoor cadence) and latches the tier it has already announced in `alerted`; any other status resets both counts and clears the latch. It has no `ok`, `since` or `last_status` fields — the entry said so until #94, which is when somebody read the class in order to reuse it. **Indoor only**: that reset-on-anything-else branch is why the outdoor poller has its own tracker — see **outdoor health**.
- **engaged** — *Historical (removed in ADR-002).* An open co2/voc **event** whose `fans_engaged` latch was set, i.e. one the Awair score had agreed with. Fans no longer read events at all, so nothing writes the latch; the `alert_events.fans_engaged` column and its history remain.
- **capped** — Per-fan flag set when a **run** hits `FAN_MAX_RUN` (90 min). While set the fans stay off *even though co2 still calls for them*, clearing only once co2 falls below `CO2_FAN_OFF`. Without the latch the cap would defeat itself — it fires while co2 is still high, and the **hysteresis band** would re-engage on the next poll.
- **event** — A row in the `events` table representing an open or closed spike/threshold violation. Rows are opened by `spikes.evaluate` and closed by `db.close_event`.
- **fan mitigation** — The whole loop: `desired_action` → `decide` → `actuate`. Runs the ceiling fans while co2 is high and stops when the air clears or the **cap** fires. Retired in #61, live again on an absolute co2 trigger as of [ADR-002](docs/decisions/002-co2-only-fan-mitigation.md).
- **fan_events** — Append-only SQLite table, one row per fan **actuate** *attempt*: `at`, `fan_id`, `action`, the verdict's `reason` verbatim, and `ok` (did the NodeMCU accept it). Written from `_command_fan` after the actuation resolves, and from `run_fan_test`, which bypasses it (#84). The durable counterpart to **fan_state**, which holds only *now* — two rows, overwritten in place. Exists because ADR-002's 0.62% duty cycle is a *replay* of the shipped rules over recorded co2, and the ADR asks for a re-measurement after the first cold month; with no history that re-measurement is another replay against the same rules. Records the four divergences a replay cannot model: a refused command is `ok = 0` (nothing else keeps it — `fan_state.last_action` deliberately holds its old value on a failed actuate), a **rate limit** drop is the *absence* of a row, a pm25 **suppressor** veto and a **capped** run are both `action = "off"` separated only by `reason`, and poller downtime is a gap. Not pruned: ~28 rows per eight weeks at the measured rate; the bound is 2,880/day on the drive path (re-issued once per **rate limit**) and 5,760/day under a pm25 veto, which bypasses the rate limit and so re-issues once per **poll** — both driven by a NodeMCU that has stopped answering rather than by bad air, and under 20 MB a month either way. A consumer counting vetoes or actuations must collapse contiguous runs of `ok = 0` rows sharing a reason: one veto against a dead NodeMCU writes thousands of identical rows.
- **fan_state** — SQLite row (one per fan) tracking `last_action` (last known / last confirmed physical state), `last_command_at` (when the poller last tried to command the fan — used for the 1-cmd/min rate limit), `run_started_at` (when the current **run** began, NULL when off) and `capped`.
- **hysteresis band** — The range between `CO2_FAN_OFF` (900 ppm) and `CO2_FAN_ON` (1000 ppm), inside which `co2_calls_for_fans` holds whatever the fan is already doing. Fans start at or above 1000 and stop below 900. Without the band a single threshold would command the fans several times a minute at a 30 s poll interval.
- **journal-mode transition** — The `PRAGMA journal_mode = WAL` in `awair.db.connect()`, and the one statement in `connect()` that does **not** honour `busy_timeout`. SQLite needs a brief exclusive lock to rewrite the file header and fails fast with `database is locked` rather than invoking the busy handler, so setting `busy_timeout` first does not cover it (#102) — it covers the SCHEMA bootstrap and `_migrate` writes after it, which are ordinary writes and do. The transition therefore carries its own bounded retry (`_set_journal_mode_wal`). It is a **once per database** event, not a per-connection one: `journal_mode` persists in the file header, so every call after the first winner is a no-op read that cannot contend. That is why the window is a fresh install — `restart.sh` starting both pollers and the web app together — and never the homelab, in WAL since its first deploy. Distinct from a **poll** or a **fetch**: nothing here is periodic.
- **run** — One unbroken stretch of a fan being driven, from the command that starts it to the command that stops it. Bounded by `FAN_MAX_RUN`; tracked per fan via `fan_state.run_started_at`. A **run** is coarser than a co2 excursion — the **hysteresis band** merges nearby excursions into one run.
- **FansConfig** — Immutable config for fan mitigation: `enabled`, `fan_host`, `fan_ids`. Built from env by `awair.fans.config_from_env`.
- **fetch** — The single-shot HTTP GET against the Awair Element Local API that returns one reading payload; built by `poller.make_fetch(url)`.
- **latest** — The `GET /api/latest` read-only JSON contract with the house hub (parsons-pulse, #70): the newest **reading** plus every open **event**, and nothing derived. Distinct from **series** (bucketed history for the dashboard) in audience as well as shape — `latest` feeds a machine, so it is **always Celsius regardless of `TEMPERATURE_UNIT`** and names its unit in the payload, and it publishes both clocks (`ts`, the Element's; `received_at`, the homelab's) because staleness must be measured on ours. Ships open events rather than a colour: the ceilings stay in `spikes.py` and the hub sorts colour house-wide, and **spike events only** — the `metric="device"` and `metric="outdoor"` health events are filtered out, since it has no measurement and the consumer sees the same outage sooner in `received_at`. An empty table is a 200 with a null reading, not an error. (aka: latest reading, /api/latest — use latest.)
- **metric** — A named channel on a reading (`co2`, `voc`, `pm25`, `temp`, `humid`, etc.); the `MetricConfig` dataclass in `awair.spikes` binds a metric to its thresholds.
- **MetricConfig** — Per-metric threshold + hysteresis config used by `spikes.evaluate` to decide whether to open, close, or renotify an event.
- **MitigationDecision** — Immutable dataclass emitted by `awair.fans.decide`: `fan_id`, target `action`, and human-readable `reason`. Consumed by `actuate`.
- **notifier** — The `awair.alerts.Notifier` object that fans an event out to ntfy; injected into `poller.handle_device_health` and `monitor.check_metrics`.
- **outdoor health** — The outdoor poller's positive liveness signal (#94): `awair.monitor.OutdoorHealth` counts consecutive non-inserting polls and `outdoor.handle_outdoor_health` opens an **event** under `metric="outdoor"` when a run reaches the threshold. Three tiers, because only one of them is ours to fix — `unreachable` (a run of `"error"`; our network or our box; the only tier that pages at high priority), `degraded` (a run of `"partial"`; Open-Meteo's air-quality half is down while weather still writes) and `stale` (a run of `"duplicate"`; upstream is not publishing). **Not `DeviceHealth` with a different threshold**, and the difference is a defect rather than a preference: **outdoor poll** returns four statuses where the indoor poller returns three, and `DeviceHealth.observe` reaches its healthy branch through a bare `else`, so `"partial"` reads there as a successful insert — measured, twenty consecutive `"partial"` polls never alert and one after an alert reports recovery. **Not `metric="device"` either**: `db.get_open_events` returns at most one open event per metric and the two pollers are separate processes against one database, so a shared key means an outdoor recovery closes the indoor poller's open row and sends a false all-clear. Filtered out of **latest** for the same reason `device` is. Threshold is polls, not wall-clock, but the notification states the duration — the outdoor cadence is 900 s against indoor's 30 s, so the same count means 5 minutes on one poller and 2.5 hours on the other. Default 4 polls (~1 hour, about one Open-Meteo publish cycle), overridable with `AWAIR_OUTDOOR_HEALTH_POLLS`. (aka: outdoor device health, outdoor liveness — use outdoor health.)
- **outdoor latest** — The `GET /api/outdoor-latest` read-only JSON contract with the house hub (parsons-pulse, #71): the newest **outdoor reading**, whole, and nothing derived. Outdoor sibling of **latest** and it inherits both of that endpoint's machine-facing rules — **source units regardless of `TEMPERATURE_UNIT`**, and an empty table is a 200 with a null reading rather than an error. Publishes three clocks, not two: `ts` (Open-Meteo's publish time), `received_at` (ours, the one to measure staleness against) and **aq_ts**. Names four units — `temp_unit`, `pressure_unit`, `wind_speed_unit`, `precipitation_unit` — being the four somebody converts: the hub renders °F, mph and inches, and this app converts **pressure** to inHg for `/api/outdoor-series` and temp to F for every browser-facing endpoint. The particulate and gas fields are deliberately unlabelled — one spelling everywhere (µg/m³), `us_aqi` dimensionless, `humid` a percent, and nobody converts them. Ships the WMO **weather_code** integer rather than a word, for the same reason **latest** ships open events rather than a colour. (aka: /api/outdoor-latest — use outdoor latest.)
- **outdoor reading** — One row in the `outdoor_readings` table produced by `awair.outdoor.parse_reading(weather, air_quality, received_at)`. Sibling of **reading** (indoor). Different cadence (15 min at source vs. 30 s indoor) and different upstream (Open-Meteo vs. Awair Element local API), so kept in its own table rather than widening `readings`. Keyed on `ts`, which is `TEXT NOT NULL PRIMARY KEY` **since #98** — the `NOT NULL` is not redundant, because SQLite keeps a longstanding compatibility bug where a non-`INTEGER PRIMARY KEY` on a rowid table gets no implicit `NOT NULL`, and the deployed table therefore accepted unlimited **unkeyed rows**. Dedup is `ON CONFLICT(ts) DO NOTHING` rather than `INSERT OR IGNORE`, and the verb is load-bearing rather than stylistic: `OR IGNORE` ignores *every* constraint violation, so under a `NOT NULL` column it returns rowcount 0 and an **outdoor poll** renders that as `"duplicate"` — the one status meaning nothing is wrong. Tightening the column without also naming the conflict target would have moved this table from #98's silent-garbage failure into #95's silent-duplicate one.
- **outdoor poll** — One iteration of `awair.outdoor.poll_once`: `fetch_weather` + `fetch_air_quality` → `parse_reading` → `insert_outdoor_reading`. An AQ-endpoint outage does not wedge the weather write — the row lands with AQ columns NULL and the poll returns `"partial"`. Returns one of `"inserted"`, `"duplicate"`, `"partial"`, `"error"`. **An unusable payload returns rather than raising** (#91) — a non-object weather block or `current`, an absent/unparseable/`null`/**clockless** `current.time`, or an AQ block whose shape cannot be read — because a raise here unwinds the `while` loop in `main()`, so one bad upstream value exited the process and systemd restarted it straight into the same value. Weather-side failures are `"error"` and log at WARNING; AQ-side ones are `"partial"`, since the weather half is still worth writing. Since #98 that covers the insert too: `insert_outdoor_reading` moved *inside* the handler and `sqlite3.Error` joined the tuple, so a bind-time `ProgrammingError` (a nested object in one of the twelve optional columns, which `parse_reading` hands to the driver unchecked) or an `OperationalError` (locked DB, full disk) is a logged `"error"` rather than a dead unit. **This reverses the #91/#93 ruling recorded here** — that a `sqlite3.Error` is "a local fault a restart can clear" and should propagate — and adopts PR #97's counter-argument for the indoor poller: a restart does not clear a full disk, and for a payload fault that has merely travelled as far as the bind it puts the poller straight back into the same upstream value, which is the crash loop #91 exists to prevent. A sustained run of errors is still reported, by **outdoor health** escalating it to `unreachable` rather than by the process dying. A clockless weather `time` is refused rather than clocked at midnight for the reason given under **aq_ts**, and refusing it is *why* nothing is stored for as long as it persists — pre-#91 a fabricated midnight `ts` took the PRIMARY KEY and made every later poll that day a silent `"duplicate"`, one row per day at INFO.
- **outdoor today** — The `GET /api/outdoor-today` read-only JSON contract with the house hub (#79): sums and extremes over `outdoor_readings` since **local midnight**, in source units. Machine-facing sibling of **outdoor latest** and it inherits both of that endpoint's rules — source units regardless of `TEMPERATURE_UNIT`, and an empty window is a 200 rather than an error. Exists because `/api/outdoor-series?range=today` *looks* like the answer and is not, for two independent reasons: it converts to display units (`_MM_PER_INCH`, hPa→inHg, °C→°F), which is the silent multiply **outdoor latest** was built to avoid, and `series.bucket` emits `avg`/`min`/`max` with no sum at all. The trap worth naming is that a consumer who tries it anyway **finds that it works**: at `range=today` the bucket is 900 s and so is the source cadence, so each bucket holds exactly one point and `avg` *equals* the raw value — summing `avg` gives the right rain total today by coincidence, and starts under-reporting silently the moment either number changes. Publishes `row_count` **and** `contributing_rows`, which are not the same number: `row_count` separates "no rain today" from "the poller has been down since 03:00" (the same old-row-vs-no-row rule `latest_outdoor_reading` is built on), while `contributing_rows` is per source column, because a column can be NULL on a row that exists — every row predating the **snowfall** migration is exactly that. A field with no values at all is `null`, never `0`. Summing rows is sound only because each row is a backward-looking sum over its own `interval` window (900 s, equal to the publish cadence) and `ts` is the primary key, so a re-poll cannot double-count one window; `outdoor.SOURCE_INTERVAL_SECONDS` warns if that ever stops holding. (aka: /api/outdoor-today, day aggregate — use outdoor today.)
- **poll** — One iteration of the poller loop: `fetch` → `parse_reading` → `insert_reading` → `check_metrics` → `check_fans`. Distinct from **fetch** — a poll wraps a fetch with DB + monitor side effects.
- **pressure** — Mean sea-level barometric pressure. Stored in the `outdoor_readings.pressure` column in hPa (Open-Meteo's native unit) and converted to inHg at the `/api/outdoor-series` boundary (`_HPA_PER_INHG = 33.8639`) but published **unconverted, as hPa**, by **outdoor latest**, which labels it `pressure_unit` precisely because those two boundaries disagree (#71). Rendered on the precipitation card as a second Y-axis layer (fixed range 28.5–31.0 inHg) using each bucket's `min` — the trough is the storm-front signal, not the average (#42).
- **reading** — One row in the `readings` table; produced by `poller.parse_reading(payload, received_at)`.
- **release** — Commanding a fan `off` once because **fan mitigation** is not driving it, as opposed to because the air cleared (`awair.fans.release_fans`, reason string `RELEASE_REASON`). A disabled poller releases rather than freezing, and then goes quiet — it does not re-command a fan switched on at the wall afterwards.
- **disabled in code** — The state `awair.fans.MITIGATION_RETIRED = True` produces: `config_from_env()` reports disabled whatever `AWAIR_FAN_MITIGATION_ENABLED` says, and the poller **release**s the fans. Called *retired* while #61 stood; ADR-002 turned it off but kept the switch, so it is now the off-ramp rather than the status quo. Distinct from **disabled**, the ordinary off position of the env var — the two have different fixes, which is why the startup banner names them separately.
- **series** — A bucketed time-window of readings for the dashboard, produced by `awair.series.bucket(points, bucket_seconds)`. **Not** a synonym for `metric_history` (which returns raw points).
- **snowfall** — Snow depth in **cm** for one **outdoor reading**'s window, as Open-Meteo publishes it (`outdoor_readings.snowfall`, #79). **Not derivable from `precipitation`**, which is the water equivalent in mm: the depth-to-water ratio moves with the snow's density, so no downstream arithmetic recovers it — which is why the hub's *"more than 4 inches of snow"* red rule needed a column rather than a formula. Published unconverted by **outdoor latest** and **outdoor today**, labelled `snowfall_unit: "cm"` — a fifth unit rather than a second use of `precipitation_unit`, because folding snow into the mm label is a silent 10x on the one number whose threshold is inches. NULL on rows predating #79, and **NULL means unknown, never "it is not snowing"**; the migration adds the column with no DEFAULT for that reason, since `DEFAULT 0` would assert across a whole history that it was not snowing. Expect NULLs for the first quarter-hour after deploy, same as **weather_code** did.
- **spike** — An event triggered by threshold + hysteresis logic in `awair.spikes`; distinct from a **stale device**, which is the health-check equivalent handled by `monitor` + `DeviceHealth`.
- **near-miss** — A pm25 reading at or above `PM25_NEAR_MISS_THRESHOLD` (50 µg/m³) but below the **suppressor** threshold (100). Logged at INFO from `check_fans` so we can watch the suppressor's headroom shrink before it ever fires (#15). Behavior-neutral — it does not change the fan verdict.
- **suppressor** — A metric that *blocks* fan mitigation rather than triggering it. PM2.5 is the sole suppressor (fans re-suspend particulate); pm25 at or above 100 µg/m³ forces fans off regardless of co2, and bypasses the rate limit doing so. Raised from 25 in ADR-002, where 25 was measured to veto 36.9% of fan-worthy time because cooking drives co2 and particulate together.
- **sync group** — uPlot's named cursor-broadcast group, `uPlot.sync("awair")`. A chart joins it by passing `cursor: { sync: { key } }` to its constructor — that config **is** the subscription (uPlot v1.6.32 ends its constructor with `syncGroup.sub(self)`), so an explicit `sync.sub(plot)` afterwards registers the chart a second time. Every entry in the group's `plots[]` is walked on each publish, so a doubled registration runs `updateCursor` twice on every peer for one cursor move — 16 subscriptions for 8 cards, until #90. The publishing chart is skipped by identity, so it pays nothing and only its peers do. Removal is leak-free in either shape: `unsub` filters *all* occurrences, and `destroy()` calls it, so `load()`'s five-minute rebuild cleans up correctly.
- **TEMPERATURE_UNIT** — Environment variable that flips the display unit for temperature. Accepts `C` (default), `F`, or `K`. Read by `awair.units.get_temperature_unit`; storage in the `readings` table is always Celsius.
- **unkeyed row** — An `outdoor_readings` row whose `ts` is NULL: not a reading of any particular moment, invisible to the dedup `ts` exists for, and sorting first under every `ORDER BY ts` (SQLite sorts NULL first). Possible only on a table predating #98. The migration **drops** them rather than deriving a `ts` from `received_at`, which would manufacture an observation time Open-Meteo never published — the same refusal recorded under **aq_ts** — and logs each dropped row whole at WARNING, not merely a count: the sensor values and `received_at` on them are real observations, and once the table is gone the journal is the only place left to recover them from. The homelab had zero of them when the migration was written (5,649 outdoor rows, measured 2026-09-09), so the drop path is defence, not cleanup.
- **weather alert** — A warning, watch or advisory published by the **National Weather Service** for the parcel, fetched from `api.weather.gov/alerts/active?point=…` on the outdoor poller's existing timer and stored in `weather_alerts` keyed on the CAP urn (`properties.id`, **not** the feature's `id`, which is a URL). Three names in this codebase are nearly this one and none of them is: `awair.alerts` is the ntfy **notifier**, `alert_events` is our own **spike** bookkeeping, and a **ceiling** alert is a threshold we set — a weather alert is someone else's warning, which we store and republish and never raise ourselves. Hence `awair/weather_alerts.py`, the `weather_alerts` table and `GET /api/weather-alerts`, all spelled out; #79 drafted the endpoint as `/api/alerts`, which beside `/api/latest`'s `open_events` would read as the other sense. Lives here rather than in the hub because this app already polls the WAN against `AWAIR_LAT`/`AWAIR_LON` and the hub's ADR-007 forbids anything but plain HTTP to a LAN IP literal (decided with Tom, 2026-09-05). **The contract is shaped around one rule: a failed poll must never render as "no alerts."** So `alerts` is `null` until a poll has succeeded and `[]` only when NWS actually said none; two clocks ship beside it (`last_attempt_at`, `last_success_at`) and the pair diverging *is* a sustained outage; nothing ever deletes a row, so "currently active" is `last_seen_at == last_success_at` (plus an `ends`/`expires` filter for when that poll goes stale) rather than "the table is empty"; and **one unreadable feature fails the whole poll**, because storing the readable subset under a successful clock would make a warning we could not parse indistinguishable from an all-clear. Severity ranking is the hub's, for the same reason card colour and the **weather_code** word are. (aka: NWS alert, /api/weather-alerts — use weather alert.)
- **weather_code** — Open-Meteo's WMO interpretation code, stored as the integer the source published (`outdoor_readings.weather_code`, #71). It is the only field in the outdoor payload that can say *"Overcast"* rather than a number; without it a weather card reading `62°F, 8 mph, 0.00 in` can never say "Raining". **The WMO-code→word mapping belongs to the hub, not here** — decided on #71 and recorded because the ticket asked for a choice. awairelement is the system of record and publishes facts; presentation is the consumer's, exactly as card colour is (see **latest**). The mapping is also display-shaped in a way storage is not — icon, short word and long phrase are three different renderings of one code — and keeping it hub-side means reworded copy ships without an awairelement deploy. NULL on rows predating #71.

## Related decisions

Load-bearing terminology choices go in `docs/decisions/` as ADRs. Link them
here when a term is contested or has a non-obvious rationale.

- [ADR-001](docs/decisions/001-retire-automatic-fan-mitigation.md) — retire
  automatic **fan mitigation** (#61). Defines **disabled in code** and
  **release**. Superseded in part by ADR-002.
- [ADR-002](docs/decisions/002-co2-only-fan-mitigation.md) — un-retire **fan
  mitigation** on an absolute co2 trigger. Defines **hysteresis band**, **run**
  and **capped**; retires **engaged**.
